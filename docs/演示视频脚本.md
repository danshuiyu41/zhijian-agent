# 演示视频脚本（时长 ≤ 5 分钟，MP4，≤ 150 MB）

## 一、拍摄前准备清单

| 项目 | 要求 |
|---|---|
| 分辨率 | 1920×1080 或 1280×720，30 fps |
| 录屏工具 | OBS Studio（推荐）或 Windows 自带 Xbox Game Bar（Win+G） |
| 浏览器缩放 | 110%，保证文字清晰 |
| 演示数据 | 提前执行 `python -m src.data` 与一次"填充演示数据"，保证看板有内容 |
| 预置状态 | 服务已启动（`python -m src.api`），浏览器已打开 `http://127.0.0.1:8077`，关闭无关标签页与通知 |
| 音频 | 建议后期配音；现场收音需配领夹麦，避免风扇噪声 |
| 字幕 | 建议全程配中文字幕（评审在嘈杂环境也能看懂） |

## 二、分镜脚本

### 镜头 1 ｜ 片头与问题引入（0:00 – 0:35）

- **画面**：标题页（作品名 + 赛道 + 队伍名），随后切到一段简短的产线质检/人工目检素材，或直接用字幕配图。
- **配音**："中小制造企业的表面质检，长期依赖人眼。连续作业几小时后，漏检率会明显上升，而招工越来越难。商用机器视觉方案动辄数万元一个工位，中小企业装不起。更麻烦的是，市面上的低成本方案只告诉你'这是什么缺陷'，却不告诉你'该怎么办'。"
- **字幕关键句**：人眼质检 → 漏检｜商用方案 → 太贵｜现有 AI → 只说是什么，不说怎么办

### 镜头 2 ｜ 系统亮相（0:35 – 0:55）

- **画面**：切到系统首页全屏，鼠标依次划过六个页签，随后停留在右上角状态徽标。
- **配音**："这是智检 Agent，一套能在普通笔记本上运行的工业表面缺陷智能检测与处置系统。整个系统不需要独立显卡，不需要专用视觉硬件。"
- **要点**：讲解时点明"检测 → 分级 → 根因分析 → 工艺处置 → 工单闭环"这条主线。

### 镜头 3 ｜ 核心检测演示：氧化铁皮（0:55 – 1:40）

- **画面**：点击左侧"压入氧化铁皮"样本 → 结果区出现标注框、等级 B、缺陷明细表与四段式建议。
- **配音**："点击一个缺陷样本。系统在 0.5 秒左右完成检测，框出缺陷位置，判定为压入氧化铁皮，置信度 0.9 以上，严重度等级 B 级，允许放行并记录。"
- **配音（重点）**："注意下面这一段——智能体给出了根因分析：除鳞水压力不足或喷嘴堵塞导致二次氧化铁皮被压入；立即处置、工艺纠正措施，以及批次追溯建议，全部附带了知识库条目的引用编号。"
- **字幕**：单图耗时 / 等级 / 引用条目 ID

### 镜头 4 ｜ 高危缺陷与工单闭环（1:40 – 2:30）

- **画面**：点击"龟裂"样本 → 等级变为 D（橙红色）→ 页面出现"⚠️ 须转人工复检"→ 切到"工单管理"页签，展示自动生成的紧急工单。
- **配音**："再试一个高危缺陷。龟裂会显著降低材料的疲劳强度，系统判定 D 级严重，建议判废并停机排查，自动生成紧急工单，责任部门是轧钢工艺科，检查项列到了加热炉温度曲线、终轧温度、卷流冷却水量。"
- **配音**："这就是'感知—决策—执行'的闭环：不只报出缺陷，而是直接推动产线动作。"
- **字幕**：D 级 → 判废停机 → 自动工单 → 责任部门 + 检查项

### 镜头 5 ｜ 可解释性与报告（2:30 – 3:05）

- **画面**：切到"Grad-CAM 热力图"页签（展示模型关注区域）→ 点击"查看/打印质检报告" → 报告中滚动，最后按 Ctrl+P 弹出打印预览（说明可导出 PDF）。
- **配音**："工业场景里，AI 不能是黑箱。这是我们自研实现的 Grad-CAM 热力图，红黄区域就是模型判定的依据，质检员可以据此快速复核。"
- **配音**："每一次检测都会生成一份完整报告：编号、时间、批次、缺陷坐标、置信度、判定结论、处置动作、标准引用全部留痕，可以直接打印存档，满足在线检测系统的可追溯要求。"
- **字幕**：可解释｜可追溯｜可打印存档

### 镜头 6 ｜ 质量看板（3:05 – 3:35）

- **画面**：切到"质量看板"，依次指向合格率、等级分布、缺陷类型分布、逐小时趋势图、实时动态表。
- **配音**："对于质量主管，系统提供看板：整体合格率、严重度等级分布、缺陷类型构成、逐小时趋势和实时节拍。缺陷构成本身就是工艺诊断的线索——如果划痕集中出现，多半是导板或辊面出了问题。"
- **字幕**：合格率｜等级分布｜缺陷构成｜趋势

### 镜头 7 ｜ 知识问答（3:35 – 4:05）

- **画面**：切到"知识库问答"，点击预设问题"龟裂缺陷的成因和工艺处置措施是什么？"，展示答案与引用条目。
- **配音**："系统内置了 18 条专业质检知识条目，覆盖六类缺陷的成因与处置、分级规则、复检规程、维护联动、历史案例和政策依据。新上岗的质检员可以直接问：'C 级缺陷需要人工复检吗？'"
- **要点**：强调"答案可溯源到条目 ID"，不是随口生成。

### 镜头 8 ｜ 手机端落地形态（4:05 – 4:35）

- **画面**：手机横屏或竖屏拍摄：浏览器打开局域网地址 → 点击上传区域 → 调用摄像头拍摄一件实物（可用带划痕的金属片、钥匙、硬币等）→ 上传后展示检测结果。
- **配音**："落地形态非常简单：质检员用手机浏览器打开系统，对着工件拍照，就能拿到判定结果和处置建议。后端可以放在车间的一台普通电脑上，数据完全不出厂。"
- **字幕**：手机拍照检测｜数据不出厂

### 镜头 9 ｜ 技术要点与政策契合（4:35 – 4:55）

- **画面**：切到"系统说明"页签，展示技术路线与政策依据列表。
- **配音**："技术上，我们采用 1.08 M 参数的轻量卷积网络加多尺度滑窗定位；严重度由'类别风险、置信度、面积占比'三个可解释因子计算；质量判定由确定性规则完成，大模型只负责解释与建议，保证判定可复现、可审计。系统核心链路零外部依赖，断网也能完整运行。这是一条低成本、可交付的质检数字化路径。"
- **字幕**：轻量化｜可解释｜确定性判定｜零依赖离线可跑

### 镜头 10 ｜ 片尾（4:55 – 5:00）

- **画面**：作品名 + 队伍信息 + 一句总结。
- **配音**："智检 Agent，让中小企业的每一件产品都被看见。"
- **字幕**：谢谢观看

## 三、录制注意事项

1. **控制时长**：硬性上限 5 分钟，建议成片 4:40–4:55，留出缓冲。
2. **先跑一遍全流程**：确认样本检测、工单生成、报告打开、看板数据均正常，再正式录制。
3. **鼠标动作放慢**：点击前停顿 0.5 秒，让观众看清位置。
4. **避免暴露个人信息**：关闭聊天软件、邮件通知，浏览器不要有其他标签页。
5. **文件名规范**：按大赛要求命名为 `校名-队伍编号-视频-作品名称.mp4`。
6. **压缩体积**：成片用 H.264 编码、码率 4–6 Mbps，5 分钟约 150–220 MB；若超限，降到 3 Mbps 或 720p。
7. **备份**：同时保留无字幕母版，便于后续修改。

## 四、现场答辩备用问答

| 提问 | 回答要点 |
|---|---|
| 你们的训练数据从哪来？ | 程序化合成的带钢缺陷数据集解决冷启动，同时已实现公开真实数据集（GC10-DET、DeepPCB、KolektorSDD2、VisA）的接入通道，并在文档中如实说明当前指标基于合成数据留出集，实际部署须用企业自有数据微调 |
| 为什么不用 YOLO？ | 三个原因：YOLO 为 AGPL-3.0，官方明确微调权重同样受约束，不利于企业交付；端到端检测需要框级标注，小厂不具备条件；滑窗分类只需图片级标签，标注门槛低且 CPU 可跑，更符合政策提出的"小样本标注缺陷数据微调" |
| 大模型会不会胡说？ | 质量判定不走大模型，放行与判废由确定性规则和阈值完成；大模型只生成解释与建议，且每条建议都携带知识库条目引用，可人工核对 |
| 没有 GPU 会不会太慢？ | 主干仅 1.08 M 参数，CPU 单窗口 10~30 ms，整图多尺度滑窗约 0.3~0.8 秒，满足离线抽检与非高速产线场景；系统支持导出 ONNX 以进一步加速 |
| 和商用机器视觉方案比，你们的价值是什么？ | 不追求替代高速产线的专用设备，而是解决中小企业"装不起、没人会调"的问题：普通相机加一台电脑即可，核心链路零依赖、可离线、数据不出厂，并且额外提供了商用方案普遍缺失的处置决策与工单闭环 |
| 怎么保证不会漏检？ | 系统计算置信度校准误差 ECE，并把低置信度结果显式转为人工复检而不是强行判定；同时通过知识库条目明确列出失效边界（低对比度、小目标、强反光、未知缺陷类型），并给出持续标注迭代的改进路径 |
