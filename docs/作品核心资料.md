```

│ 应用层  单文件 Web 前端（检测 / 看板 / 工单 / 诊断）                    │
│         FastAPI REST 接口 · 质检报告生成（MD / HTML / JSON）           │

│         数据集：程序化合成 + 公开真实数据 + 企业自有数据（三级策略）        │
└─────────────────────────────────────────────────────────────────────┘
```

## 二、算法流程

### 2.1 检测与定位

| 步骤 | 处理 | 说明 |
|---|---|---|
| 1 | 灰度化 | 表面缺陷以纹理为主，灰度足够且省算力 |
| 2 | 多尺度滑窗 | 尺度 1.0 与 0.6，窗口 224，步长 112（50% 重叠） |
| 3 | 批量推理 | 批大小 32，`torch.inference_mode()` + 多线程 |
| 4 | 置信度筛选 | 阈值 0.55，排除洁净类别 |
| 5 | **候选框融合** | 占较小框交叠度 ≥ 0.30 且并集膨胀 ≤ 1.6 倍则合并为同一缺陷 |
| 6 | 按类 NMS | IoU 阈值 0.35 |
| 7 | 严重度评分 | 见 2.2 |
| 8 | 风险过滤 | 面积占比低于阈值丢弃 |

**候选框融合是本项目的一处关键改进。** 滑窗 50% 重叠 + 双尺度会导致同一缺陷产生 5~7 个高度重叠的框；仅靠 NMS 无法解决，因为不同尺度的窗口 IoU 很低但显然是同一缺陷。融合引入"并集膨胀约束"，避免链式重叠把框一路并到覆盖全图（开发中实测出现过 256×256 的全图框）。

### 2.2 严重度分级公式（v2）

```
severity = 100 · [ w_risk · R + (1 - w_risk) · ( w_conf · C + w_area · A ) ]

w_risk = 0.55, w_conf = 0.20, w_area = 0.25（后两者内部归一化）
R = 类别风险基线分 ∈ { high: 0.70, mid: 0.42, low: 0.18 }
C = 检出置信度
A = min( min(1, sqrt(area / 0.05)), 0.30 )
```

分级映射：A ≤ 28 放行；B ≤ 42 放行并记录；C ≤ 60 人工复检；D ≤ 80 判废并停机排查；E ≤ 100 紧急停机并隔离批次。

**公式经过三轮实测校准**（详见设计说明书 4.4.1）：

| 轮次 | 问题 | 修正 |
|---|---|---|
| 一 | 小缺陷误判 D 级 | 面积项改次线性变换 `sqrt` |
| 二 | 面积项恒为满分（滑窗框占全图 77%~100%） | 设面积项饱和上限 0.30 |
| 三 | **等级退化，只有 A 和 D** | 风险改为**基线先验**而非分数，改嵌套加权 |

第三轮的根因是：旧公式中风险项自身贡献 14~40 分，直接跨越多个等级区间，导致高危恒判 D、低危常年卡 C，B 级无人落入。v2 让风险只做基线（占 55%），其余交给尺度与置信度决定升降级。

**v2 实测效果**：龟裂/夹杂 → D；斑块/麻点/划痕 → C；压入氧化铁皮 → B；洁净 → A。理论网格 54 组合覆盖 B 19 / C 23 / D 12。

### 2.3 未知缺陷识别（开集识别）

闭集 7 分类的问题是：无论输入什么，模型一定会在已知类里挑一个，并可能给出高置信度。产线推出新缺陷时，这会把全新问题掩盖成"高置信度的错误分类"。

实现：取分类头之前的 576 维特征（L2 归一化）建立特征库，推理时算 k 近邻距离（k=5），超过阈值即判「疑似未知缺陷，转人工」。

| 阈值 | 已知通过率 | 未知拦截率 |
|---|---|---|
| 0.2812 | 28.6% | 98.3% |
| 0.4151 | 85.7% | 66.7% |
| **0.5155（采用）** | **97.1%** | **48.3%** |
| 0.6438（保守标定） | 100% | 25.0% |

采用在"已知通过率 ≥ 95%"前提下最优的阈值。**诚实说明**：这是安全阀级别，不是精确识别级别；且滑窗机制带来一个固有困难——一张图有几十个窗口，只要有一个窗口离已知簇近，整图就容易判为已知。

### 3.1 关键技术点

**① 数据策略：三级递进**

```
程序化合成（冷启动，标签免费）
   ↓
公开真实数据集（建立可信基线）
   ↓
企业自有数据（实际部署微调）
```

合成数据生成器按缺陷形成机理建模六类缺陷：龟裂为晶界网状裂纹、夹杂为深色不规则块状压入物、斑块为片状氧化区、麻点为密集小凹坑、压入氧化铁皮为轧制方向条带、划痕为细长线状损伤。尺度与对比度可参数化，用于构造鲁棒性压力测试集。

**② 推理性能取舍（实测驱动）**

| 环节 | 耗时 | 占比 |
|---|---|---|
| 滑窗推理 | 177 ms | 8% |
| **Grad-CAM 热力图** | **1905 ms** | **90%** |
| 标注图 + base64 | 24 ms | 1% |
| 智能体检索与工单 | <5 ms | <1% |
| 落库 | 12 ms | 1% |

由于热力图仅用于人工复核、不参与判定，将其从同步链路拆出为独立接口 `/api/heatmap/{id}`：判定先快速返回（实测 HTTP 往返 **296 ms**），热力图随后异步补齐。**这使界面首屏延迟从 2598 ms 降到 296 ms，提升 8.8 倍。**

**③ 智能体不参与质量判定**

放行/判废由确定性规则与阈值完成，大模型只生成解释与建议。理由是工业质量判定必须可复现、可审计。三级后端按可用性降级，`rule` 保证任何环境都能演示完整链路。

**④ 诊断助手的定位（有意拒答）**

知识问答实测发现：回答"龟裂的成因是什么"这类问题，对产线工程师毫无增量价值。因此把模块重新定位为**从缺陷现象反查排查方向**，并显式拒答基础原理：

| 提问 | 判定 | 行为 |
|---|---|---|
| 龟裂的成因是什么 | basic | **拒答** + 引导 |
| 龟裂比例连续三班次上升，先查什么 | diagnostic | 给出排查顺序 |

知识库配套增加 6 条**诊断条目**（排查顺序 + 现场判据 + 验证方式），例如"压入氧化铁皮的条带横向位置直接对应除鳞集管的某一组喷嘴"。

## 四、实测指标

### 4.1 测试环境

Windows / Python 3.10 / PyTorch 2.12（**CPU 版，无独立显卡**）/ OpenCV 4.11 / FastAPI

### 4.2 模型性能

| 指标 | 验证集 | 测试集 |
|---|---|---|
| 准确率 | 100.00% | 100.00% |
| Top-2 准确率 | 100.00% | 100.00% |
| 宏平均 F1 | 1.0000 | 1.0000 |
| 加权 F1 | 1.0000 | 1.0000 |
| ECE 校准误差 | 0.0521 | 0.0497 |
| 单图分类耗时 | 9.28 ms | 9.92 ms |

模型参数量 **1.077 M**，权重文件 4.23 MB，训练耗时约 40 分钟（CPU）。

### 4.3 鲁棒性（受控退化实验）

| 难度档位 | 检出率 | 漏检率 | 过杀率 | 缺陷分类准确率 |
|---|---|---|---|---|
| L1 正常 | 100.00% | 0.00% | 0.00% | 99.44% |
| L2 小尺度（尺寸约 45%） | 100.00% | 0.00% | 0.00% | 97.78% |
| **L3 小尺度+低对比度** | **85.00%** | **15.00%** | 0.00% | **79.44%** |

结论：常规与小尺度条件下检出率 100%、过杀率 0%；**小尺度叠加低对比度是主要失效模式**。

### 4.4 节拍与开销

| 模式 | 单件耗时 | 换算 |
|---|---|---|
| 纯检测 | 91 ms | 11 件/秒 |
| 检测+智能体+落库 | 101 ms | 10 件/秒 |
| 界面链路（含传输） | 296 ms | 3.4 件/秒 |
| 检测+热力图复核 | 1812 ms | 0.6 件/秒 |

可匹配 120 件/分钟以内的产线节拍。

## 五、可解释性验证

使用自研 Grad-CAM 生成类激活热力图，并人工核对高亮区与真实缺陷位置是否吻合：

| 缺陷 | 热力图高亮位置 | 结论 |
|---|---|---|
| 夹杂 | 深色块状物上 | 吻合 |
| 斑块 | 两个亮斑上 | 吻合 |
| 麻点 | 点阵区域 | 吻合 |
| 压入氧化铁皮 | 条带状压痕 | 吻合 |
| 龟裂 | 网状裂纹 | 吻合 |
| 划痕 | 线状损伤 | 吻合 |

**意义**：证明模型依据的是缺陷本身，而非背景纹理或光照。这是工业 AI 落地最需要排除的风险。

## 六、工程可靠性

| 措施 | 说明 |
|---|---|
| 零外部依赖 | 检索、可解释性、报告生成均自研；不引入 CDN 字体/图标库/前端框架 |
| 离线可用 | 前端全部资源本地化；模型权重与 torch 缓存随作品打包 |
| 三级后端降级 | 无网络、无本地大模型时，规则后端保证完整链路可演示 |
| 数据不出厂 | 默认全本地运行，图片与判定结果存本机 |
| 全链路留痕 | 检测编号、时间、批次、缺陷坐标、置信度、判定、耗时、引用条目全部入库 |

## 八、作品定位与边界

**适用范围**：热轧带钢、钢板类金属表面的常见外观缺陷分类与定位，单件检测 91 ms。

**不适用**：内部缺陷与力学性能问题（需超声、X 光等无损检测）；缺陷对比度极低且尺度小于成像分辨率的情况（实测 L3 档漏检率 15%）；强反光、油污、水渍造成的伪缺陷。

**数据说明（须如实告知）**：当前全部指标基于**程序化合成的缺陷数据集**留出测试集。合成数据解决的是"冷启动无数据"问题，**不能替代真实产线数据**。系统已实现公开真实数据集（GC10-DET / DeepPCB / KolektorSDD / VisA）的接入通道与断点续传下载器；实际部署须以企业自有数据重新训练与标定，因只需图片级标签，将照片按类别文件夹整理后即可完成，无需框级标注。
