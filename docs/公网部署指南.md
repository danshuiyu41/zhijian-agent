# 公网部署指南（必须做，否则作品无效）

> **官方硬性要求**（2026 年赛事通知 第三条 (5)）：
> 「参赛作品应涉及联网功能，应具备**公网内的联通性**且能流畅运行。对于**仅限在某个专网或校园网上访问而无法通过公网访问的作品，由于无法评审，将被视为无效参赛作品**。」
>
> 官方链接：https://jwc.cnu.edu.cn/tzgg/lb1/d1c672e6ffc04948b7b14be28ca9d1b9.htm

本系统默认监听 `127.0.0.1:8077`，**这是本机回环地址，外部访问不到**，必须做本文的任一种方案。

## 方案对比

| 方案 | 成本 | 耗时 | 适合 | 稳定性 |
|---|---|---|---|---|
| **A. 内网穿透** | 免费（有免费额度） | 20 分钟 | 演示期临时上线 | 中 |
| **B. 云服务器** | 学生机约 ¥10/月 | 1–2 小时 | 长期稳定 | 高 |
| **C. 学校服务器** | 0 | 视老师配合 | 有资源的话最优 | 高 |

**建议**：先做 A（当天就能通），有时间再上 B。

## 方案 A：内网穿透（最省事）

原理：在本地跑一个小客户端，它主动连接穿透服务商的公网服务器，把 `8077` 端口映射成一个公网域名。

### A-1 cpolar（推荐，免费额度够演示）

1. 注册：https://www.cpolar.com
2. 下载 Windows 客户端并安装
3. 在 https://dashboard.cpolar.com/auth 复制你的 authtoken
4. 本机执行一次：

```bat
cpolar authtoken 你的authtoken
```

5. **先启动本项目服务**：

```bat
cd /d D:\deeps\bisai
python start.py --port 8077
```

6. **另开一个命令行窗口**，启动隧道：

```bat
cpolar http 8077
```

7. 屏幕上会打印一个公网地址，形如：

```
Forwarding   https://xxxxxxxx.r2.cpolar.top -> http://localhost:8077
```

**这个 `https://...` 地址就是提交给评委的地址**，任何人都能打开。

### A-2 natapp

1. 注册：https://natapp.cn
2. 购买免费隧道，协议选 Web，本地端口填 `8077`
3. 下载客户端，同目录放 `config.ini`（把页面给的 authtoken 填进去）
4. 先启动 `python start.py`，再执行：

```bat
natapp -authtoken=你的authtoken
```

### A-3 花生壳

图形化软件，需实名认证。映射内网主机 `127.0.0.1`、端口 `8077` 即可。

### A 方案的注意点

| 问题 | 说明 |
|---|---|
| **电脑必须一直开着** | 关了机地址就失效。演示前务必确认服务在跑 |
| 免费域名会变 | cpolar 免费版每次重启隧道域名可能变化，**演示前重新取一次地址**，别用旧的 |
| 免费版有连接数限制 | 一般够用；若卡顿升级为付费版 |
| 首次打开慢 | 穿透线路首次加载静态资源会慢几秒，属正常 |

### 上线后必须自测

用**手机流量**（不是连家里 WiFi）打开那个公网地址，确认：
- 页面能正常打开
- 能上传图片并出结果
- 看板能显示数据

只有手机流量能打开，才算真正"公网可访问"。

## 方案 B：云服务器（长期稳定）

### B-1 买服务器

阿里云 / 腾讯云 / 华为云，「学生机」或「轻量应用服务器」即可：

| 配置 | 要求 |
|---|---|
| 系统 | Ubuntu 22.04（推荐）或 Windows Server |
| CPU | 2 核 |
| 内存 | **≥ 4 GB**（PyTorch 推理需要，2G 会吃力） |
| 带宽 | 3 Mbps 以上 |
| 费用 | 约 ¥10/月（学生优惠） |

选 **Ubuntu** 更省钱（无图形界面，资源占用低）。

### B-2 部署（Ubuntu）

```bash
# 1. 装 Python 与依赖
sudo apt update && sudo apt install -y python3-pip git
pip3 install torch torchvision --index-url https://download.pytorch.org/whl/cpu
pip3 install opencv-python-headless numpy fastapi uvicorn python-multipart matplotlib pyyaml pillow

# 2. 拉代码（用你自己的仓库）
git clone git@github.com:danshuiyu41/zhijian-agent.git
cd zhijian-agent

# 3. 重建数据与模型（仓库里不含数据集和权重）
python3 -m src.pipeline

# 4. 启动服务（绑 0.0.0.0 才能被外部访问）
python3 start.py --host 0.0.0.0 --port 8077
```

### B-3 让它后台常驻

```bash
# 简单方式
nohup python3 start.py --host 0.0.0.0 --port 8077 > server.log 2>&1 &

# 更稳的方式：systemd（开机自启、崩溃自动重启）
sudo tee /etc/systemd/system/zhijian.service > /dev/null <<'EOF'
[Unit]
Description=Zhijian Agent
After=network.target

[Service]
Type=simple
WorkingDirectory=/root/zhijian-agent
ExecStart=/usr/bin/python3 start.py --host 0.0.0.0 --port 8077
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now zhijian
sudo systemctl status zhijian      # 查看运行状态
```

### B-4 开放防火墙与安全组

| 位置 | 操作 |
|---|---|
| 云控制台**安全组** | 添加入方向规则：TCP `8077`，来源 `0.0.0.0/0` |
| 服务器本机防火墙 | `sudo ufw allow 8077/tcp` |

**两个都要开**，只开一个访问不到——这是最常见的坑。

### B-5 访问地址

```
http://服务器公网IP:8077
```

想用域名 + HTTPS 的话，后面可加 Nginx 反向代理（本次演示非必需）。

## 上线后要改的地方

部署到公网后，有几处需要同步改：

### 1. 提交材料里写清访问方式

在 `作品简介`、`软件设计文档` 里补一句：

```
系统已部署至公网，可在线访问验证：http://你的地址
演示账号：无需登录（演示版开放访问）
```

### 2. 加访问限制（可选但建议）

公网开放有风险，建议加最简单的口令保护，避免被扫描到后乱传数据：

在 `config/config.yaml` 里加：

```yaml
server:
  host: "0.0.0.0"
  port: 8077
  access_token: "zj2026"      # 访问口令，留空则不校验
```

然后在 `src/api.py` 加一层依赖校验（详见下方代码片段）。

### 3. 关掉可能泄露信息的接口

`/docs`（FastAPI 自动文档）与 `/api/demo/seed`（填充演示数据）在公网环境建议关闭或加口令。

## 演示当天的检查清单

- [ ] 公网地址用**手机流量**能打开
- [ ] 首页状态徽标是绿色「就绪」
- [ ] 上传一张图能出结果（≤ 300 ms）
- [ ] 看板有数据（提前执行过一次填充）
- [ ] 工单页有记录
- [ ] 报告能打开并打印
- [ ] 备用方案：**本机 localhost** 也要能跑（万一穿透挂了，现场用自己电脑演示，公网地址给评委事后访问）
- [ ] 提前把地址、二维码写进 PPT 和文档

> **重要**：现场演示时同时准备**本机运行**和**公网访问**两套。
> 内网穿透受网络影响，现场万一卡住，立刻切回本机演示，别在台上等。

## 快速决策

```
今天就要能访问   → 方案 A（cpolar），20 分钟
要长期稳定       → 方案 B（云服务器），1–2 小时
学校有资源       → 先问老师（方案 C）
```

**三种可以叠加**：先用 A 应急，再上 B 做正式提交地址。
