## 1 作品概述

### 1.1 作品简介

"智检 Agent" 是一套面向中小制造企业的**工业表面缺陷智能检测与处置智能体系统**。它把一次质检拆成五个连续环节并全部自动化：

```
拍照/上传  →  缺陷检测与定位  →  严重度分级  →  智能体根因分析与工艺处置  →  工单与报告闭环
```

系统在一台普通笔记本电脑（无独立显卡）上即可完成训练与实时检测，单张图像检测耗时约 0.3~0.8 秒，整机不含任何专用视觉硬件。

### 1.2 解决的问题

中小企业表面质检面临三重矛盾：

1. **人力矛盾**：质检岗位依赖人眼，连续工作 8 小时后漏检率显著上升，且招工日益困难。
2. **成本矛盾**：商用机器视觉整机方案单工位投入高，中小企业难以承担。
3. **数据矛盾**：工厂带宽有限、工艺数据敏感，"数据不出厂"是硬约束，纯云端方案难以落地。

更关键的是，现有低成本方案普遍**只输出"是什么缺陷"，不输出"该怎么办"**。产线真正需要的是处置决策：根因在哪、调什么参数、要不要停机、同批次怎么办。本作品的智能体正是补齐这一环。

### 1.3 主要功能

| 序号 | 功能 | 说明 |
|---|---|---|
| 1 | 缺陷检测 | 多尺度滑窗 + 轻量 CNN，检出六类表面缺陷并框出位置 |
| 2 | 严重度分级 | 类别风险 × 置信度 × 面积占比 → A/B/C/D/E 五级与处置动作 |
| 3 | 可解释性 | Grad-CAM 热力图输出模型关注区域，支持人工复核 |
| 4 | 处置智能体 | 检索标准知识库，生成根因分析、立即处置、工艺纠正、批次追溯建议 |
| 5 | 工单闭环 | 按缺陷类型自动生成维修/工艺工单，联动责任部门与检查项 |
| 6 | 质量看板 | 合格率、等级分布、缺陷类型分布、逐小时趋势、节拍统计 |
| 7 | 报告输出 | 一键生成 Markdown / HTML（可打印为 PDF）/ JSON 质检报告 |
| 8 | 知识问答 | 面向质检员的自然语言问答，结论可溯源到知识库条目 |

## 3 总体设计

### 3.1 系统架构

```
┌──────────────────────────────────────────────────────────────────┐
│  应用层  Web 前端（检测 / 看板 / 记录 / 工单 / 知识问答 / 说明）      │
│          FastAPI REST 接口 + 质检报告生成（MD / HTML / JSON）        │
├──────────────────────────────────────────────────────────────────┤
│  决策层  质检处置智能体 QualityAgent                                │
│          工具：retrieve_standard / severity_grade / create_work_order│
│                trace_batch / self_check                             │
│          后端：rule（确定性）→ ollama（本地）→ openai_compat（云）     │
│          检索：BM25 + 字符 n-gram 混合（知识库 18 条专业条目）         │
├──────────────────────────────────────────────────────────────────┤
│  感知层  图像预处理 → 多尺度滑窗 → MobileNetV3-Small 批量推理          │
│          → 按类 NMS → 严重度评分 → Grad-CAM 可解释性                 │
├──────────────────────────────────────────────────────────────────┤
│  数据层  SQLite（检测记录 / 工单 / 检索留痕）                          │
│          数据集：程序化合成 + 公开真实数据（可扩展企业自有数据）        │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 技术选型与理由

| 环节 | 选型 | 选择理由 |
|---|---|---|
| 检测主干 | MobileNetV3-Small（1.08 M 参数） | CPU 单窗口推理 10~30 ms，满足无 GPU 环境；BSD-3 许可，便于声称可交付企业 |
| 定位方式 | 分类器 + 多尺度滑窗 + 按类 NMS | 只需图片级标签即可训练，大幅降低标注门槛；对应政策"小样本标注缺陷数据微调" |
| 可解释性 | Grad-CAM（自研实现） | 不引入额外依赖；满足在线检测系统可追溯与人工复核要求 |
| 知识检索 | 自研 BM25 + 字符 n-gram 混合 | 中文专业术语场景下字符 n-gram 召回优于词典分词；零外部依赖，演示机不联网也能跑 |
| 智能体后端 | 规则 / Ollama / OpenAI 兼容 API 三级降级 | 规则后端永远可用且确定性，大模型仅用于增强表达，避免幻觉影响质量判定 |
| Web 框架 | FastAPI + 原生 HTML/CSS/JS | 无前端构建链路，单机双击即用；评委可离线打开 |
| 存储 | Python 标准库 sqlite3 | 零安装、单文件、便于随作品打包与人工查看 |
| 模型导出 | ONNX（可选） | 便于部署到无 PyTorch 环境的工控机，规避框架依赖冲突 |

### 3.3 关键设计决策

**决策一：不把大模型放在质量判定路径上。**
放行/判废由确定性的规则与阈值完成，大模型只负责生成解释与建议。理由是工业质量判定必须可复现、可审计，不能受模型随机性影响。

**决策二：定位用滑窗而非端到端检测器。**
本项目一度考虑 YOLO 系列，最终放弃，原因有三：其一，YOLO 采用 AGPL-3.0，官方许可页明确将"自训练/微调的权重"也纳入约束，不利于声称可交付企业；其二，端到端检测需要框级标注，小厂不具备条件；其三，滑窗分类在 CPU 上的工程复杂度更低、可解释性更强。

**决策三：三级后端降级。**
比赛演示现场可能无网络、无本地大模型。规则后端保证"任何环境都能演示完整链路"，这是工程可靠性的底线。

## 4 功能模块设计

### 4.1 数据模块

| 模块 | 文件 | 职责 |
|---|---|---|
| 合成数据生成 | `src/data_generate.py` | 程序化合成六类带钢缺陷与洁净样本，参数化可控、可复现 |
| 真实数据接入 | `src/data_real.py`、`src/data_github.py` | 下载整理公开真实缺陷数据集，统一为 `normal/defect` 结构 |
| 数据索引 | `src/data.py` | 分层抽样划分、归一化统计量估计、PyTorch Dataset 封装 |
| 数据核验 | `src/visualize_data.py` | 类别拼图抽样，人工核验数据质量 |

**合成缺陷的物理建模**：基础纹理由轧制方向条纹 + 分形噪声 + 低频光照不均合成；六类缺陷按形成机理分别建模——龟裂为晶界网状裂纹，夹杂为深色不规则块状压入物，斑块为片状氧化区并抹除部分纹理，麻点为密集小凹坑，压入氧化铁皮为沿轧制方向的条带压痕并伴随细裂纹，划痕为细长线状机械损伤。

**三层数据策略**：合成数据解决冷启动 → 公开真实数据建立可信基线 → 企业自有数据微调落地。这一路线直接回应工业界"缺陷样本稀缺、冷启动无数据"的核心痛点。

### 4.2 模型模块

`src/model.py` 提供轻量缺陷分类器与 Grad-CAM：

- 主干：MobileNetV3-Small，参数量 1.08 M；
- 分类头：Dropout → Linear(576→256) → GELU → Dropout → Linear(256→7)；
- 输入：单通道灰度复制为 3 通道，兼容 ImageNet 预训练权重；
- 类别空间：6 类缺陷 + 1 类洁净 = 7 类；
- Grad-CAM：对主干最后卷积块做梯度加权，输出类激活热力图。

> 开发中记录了两个 torchvision 使用陷阱，已写入代码注释并加入自检脚本 `src/selfcheck_model.py`：① `mobilenet_v3_*` 直接调用 `net(x)` 返回的是**池化分类后的向量**而非特征图，必须取 `net.features`；② `resnet18` 的 `forward` 内部依赖 `avgpool` 才能正确 `flatten`，将 `avgpool` 置为 `Identity` 会导致特征维度错误。

### 4.3 训练模块

`src/train.py` 流程：加载索引 → 类别加权交叉熵 → AdamW + 余弦退火 → 早停 → 最优权重落盘 → 测试集评估 → 生成训练曲线与混淆矩阵 → 可选导出 ONNX。

评估指标包括：总体准确率、Top-2 准确率、宏平均/加权平均 P-R-F1、**期望校准误差 ECE**、逐类别 P/R/F1、混淆矩阵、单图推理耗时。其中 ECE 用于衡量置信度是否可信——在"低置信度转人工复检"的策略下，校准质量直接决定该策略是否有效。

### 4.4 推理模块

`src/infer.py` 实现滑窗检测：

1. 图像灰度化；
2. 多尺度滑窗切块（尺度 1.0 与 0.6，窗口 224，步长 112），兼顾小目标与大缺陷；
3. 批量前向（批大小 32，`torch.inference_mode()` + 多线程），取非洁净类别；
4. 依置信度阈值过滤；
5. 按类别执行 NMS（IoU 阈值 0.35）合并重叠窗口；
6. 计算面积占比并做严重度评分；
7. 输出结构化结果与可视化（标注图 + Grad-CAM 热力图）。

**严重度评分公式（v2）**：

```
severity = 100 · [ w_risk · R + (1 - w_risk) · ( w_conf · C + w_area · A ) ]

w_risk = 0.55, w_conf = 0.20, w_area = 0.25（后两者内部归一化后为 0.44 / 0.56）
R = 类别风险基线分 ∈ {high: 0.70, mid: 0.42, low: 0.18}
C = 检出置信度
A = min( min(1, sqrt(area / 0.05)), 0.30 )
```

分级映射：A ≤ 28 放行；B ≤ 42 放行并记录；C ≤ 60 人工复检；D ≤ 80 判废并停机排查；E ≤ 100 紧急停机并隔离批次。

#### 4.4.1 分级公式的三轮校准（实测驱动）

分级公式是本项目迭代次数最多的部分，前后经过三轮实测校准，完整记录如下——这是一个"先实现、再测量、后修正"的典型工程过程。

**第一轮问题：分级过于激进。**
初版按线性面积占比评分，一个仅占图像面积 1% 的小缺陷在置信度 0.98 时也被判 D 级。

*修正*：面积项改为次线性变换 `sqrt(area / area_ref)`，压缩小尺度缺陷的贡献。

**第二轮问题：面积项恒为满分。**
进一步诊断（`src/diag_infer.py`）发现检测框实测面积占比为 **0.77~1.0**——滑窗分类只能给出「窗口内存在某类缺陷」，返回的框就是整个滑窗。此时面积项恒为满分，所有缺陷都被判 E 级。

*修正*：为面积项设置饱和上限 `area_cap = 0.30`。同时提供 `model.refine_topn` 选项，可对置信度最高的 N 个窗口用 Grad-CAM 反传收紧框边界（**默认关闭**：每窗口一次反向传播会把单图耗时从约 0.1 秒推到秒级，不适合现场演示）。

**第三轮问题：等级退化，只有 A 和 D。**（由实际演示中发现）
此时公式为 `100·(0.40·R + 0.25·C + 0.35·A)`，R 取 1.0/0.65/0.35。逐项拆解后定位到根因：**风险项自身就贡献 14~40 分，直接跨越多个等级区间**——

| 类型 | 风险项 | 置信项(×0.25) | 面积项(×0.35) | 总分 | 落档 |
|---|---|---|---|---|---|
| 高危(1.0) | 40 | 23 | ≤10.5 | ~73.5 | 恒 D |
| 中危(0.65) | 26 | 23 | ≤10.5 | ~59.5 | 恒 C |
| 低危(0.35) | 14 | 23 | ≤10.5 | ~47.5 | 恒 C |

中危与低危相差 12 分却只跨一档，B 级（28~42）几乎没有缺陷能落入。**根因是把"风险"当成了分数而不是分级先验。**

*修正*：改为**嵌套加权**（v2 公式），把风险降为占 `w_risk = 0.55` 的**基线先验**，其余 45% 权重交给「缺陷相对尺度 + 模型置信度」，从而形成"风险定基线、尺度与置信度决定升降级"的行为。

**v2 实测效果**（`python -m src.diag_grade` 与 `src/diag_infer.py` 输出）：

| 缺陷类型 | 风险档 | 实测等级 | 说明 |
|---|---|---|---|
| 龟裂、夹杂 | 高危 | **D** | 判废并停机排查 |
| 斑块、麻点、划痕 | 中危 | **C** | 转人工复检 |
| 压入氧化铁皮 | 低危 | **B** | 放行并记录 |
| 洁净样本 | — | **A** | 合格放行 |
| （E 级保留给致命情形） | | | 理论网格中不出现，作为保留档 |

理论网格覆盖统计（风险×置信度×面积 3×3×6 = 54 组合）：**B 19 例、C 23 例、D 12 例**，梯度充分。三级诊断脚本 `src/diag_grade.py`、`src/diag_infer.py`、`src/selftest_e2e.py` 随作品交付，可在其他产线上重新标定。

> **诚实说明**：受滑窗分类定位精度的限制，面积项在多数检测中仍会触及上限，因此**当前分级的主要区分依据是"缺陷类型风险 + 模型置信度"**，面积项起补偿与限幅作用。若需要让面积真正参与分级，可开启 `model.refine_topn` 获得更紧的缺陷边界，代价是单图耗时上升。

### 4.5 知识检索模块

`src/rag.py` 实现零依赖的中文检索：

- 分词：中文字符 2-gram 与 3-gram + 英文/数字按词切分；
- 打分：BM25（k1=1.5, b=0.75）逐项累加，IDF 平滑；
- 混合：`score = α · BM25_norm + (1-α) · n-gram 覆盖率`，α=0.65，弥补短查询下 BM25 失效；
- 字段加权：标题权重 2.0，体现"标准条款检索"的直觉。

知识库 `knowledge/quality_kb.json` 共 18 条专业条目，覆盖：六类缺陷的成因与工艺处置、严重度分级规则、可追溯性要求、人工复检规程、设备维护联动规程、历史案例、工艺环节对照表、系统适用边界、成本效益测算口径、政策依据。

### 4.6 智能体模块

`src/agent.py` 的 `QualityAgent` 提供五个工具并编排推理：

| 工具 | 作用 |
|---|---|
| `retrieve_standard(query)` | 检索标准与工艺知识，返回带分数的条目 |
| `severity_grade(score)` | 严重度分级 |
| `create_work_order(det)` | 按规则表生成工单（责任部门、检查项、是否停机、是否隔离批次） |
| `trace_batch(det)` | 生成批次追溯建议 |
| `self_check(result)` | 置信度自检，判断是否需人工复检 |

推理流程：无缺陷则直接放行；有缺陷则按缺陷类型分别检索证据并去重合并，再用规则后端生成四段式建议（根因分析 / 立即处置 / 工艺纠正 / 批次追溯），若配置了本地或云端大模型后端则在规则结论基础上增强表达，最后调用自检与工单工具闭环。所有建议携带知识库条目 ID，实现结论可溯源。

### 4.7 接口与应用模块

`src/api.py` 提供 15 个 REST 接口（详见第 8 章接口清单）；`src/report.py` 支持 Markdown / HTML / JSON 三种报告格式，HTML 报告可直接在浏览器打印为 PDF，规避已归档的 wkhtmltopdf；`src/db.py` 负责检测记录、工单与检索留痕的持久化。

前端 `web/index.html` 为单文件原生实现，包含六个页签：智能检测、质量看板、检测记录、工单管理、知识库问答、系统说明。图像上传支持 `<input capture="environment">`，用手机浏览器打开即可调用摄像头拍照检测。

## 5 关键技术与实现

### 5.1 多尺度滑窗与 NMS 合并

工业缺陷尺度差异大：同一产线可能同时存在毫米级麻点与厘米级条带状压痕。单一窗口尺寸无法兼顾，因此采用 1.0 与 0.6 双尺度滑窗，窗口 224、步长 112（50% 重叠）。推理后按类别分别执行 NMS，IoU 阈值 0.35，避免同一缺陷被多个窗口重复计数。

### 5.2 界面设计与信息架构（Apple 设计语言）

前端经历了两轮调整，最终形成 5 个页签的结构。这里如实记录两轮的判断依据，因为它体现了一个常见的界面设计误区。

**第一轮：功能平铺。**
初版把系统所有能力平铺成六个页签（检测 / 看板 / 记录 / 工单 / 知识问答 / 系统说明），信息密度过高、主次不分。

**第二轮：过度精简。**
为追求"整洁"，把页签砍到 3 个（检测 / 看板 / 问答），并删掉了工单页、系统信息页、演示样本、热力图对比。结果**功能缺失**：闭环能力不可见、技术参数无处可查、可解释性无法现场演示。

**最终结构（5 个页签）**：判断标准不是"页面多少"，而是**每个页签是否对应演示主线上一个真实环节**。

| 页签 | 承载内容 | 对应演示环节 |
|---|---|---|
| 检测 | 上传/拍照、样本快选、结论、关键数字、四段式处置建议、缺陷明细、**原图/标注/热力图三联对照**、报告导出 | 感知与决策 |
| 看板 | 时间范围切换、6 项 KPI、等级分布、缺陷类型构成、逐小时趋势、**过程洞察**（把缺陷构成翻译成工艺排查方向） | 质量管理 |
| 工单 | 工单列表、状态筛选、优先级/停机/隔离批次标记、检查项清单、状态流转 | 闭环执行 |
| 问答 | 自然语言问答 + 知识库原文检索双通道 | 知识沉淀 |
| 关于 | 技术参数、执行标准、严重度分级表、政策依据、技术路线时间轴、使用边界 | 答辩支撑 |

**过程洞察**是本轮新增的关键能力：光有数字不构成管理价值，系统会依据当前缺陷构成自动给出排查方向（如"划痕占比最高 → 优先排查导线接触部件与跑偏纠偏系统"），把看板从"展示数据"升级为"给出动作"。

**视觉规范（`web/design-system.css`，约 400 行，按 token 组织）**：

1. **内容优先但不阉割功能**：装饰做减法，能力做加法；
2. **层级靠尺寸与字重**：主标题 34px/700、卡片标题 17px/600、正文 15px/400、次要信息 13px/400 且降为次级色——苹果很少用颜色区分层级，主要靠字重与灰度；
3. **材质（Material）**：导航栏使用 `backdrop-filter: saturate(180%) blur(20px)` 毛玻璃 + 半透明底，滚动时内容从下方穿过；
4. **描边替代阴影**：默认只用 1px 细描边划分区块，避免页面出现大量"浮起来的盒子"；
5. **连续圆角**：卡片 18px、控件 10px、胶囊 980px；
6. **单一强调色**：仅用系统蓝 `#0071e3` 表达可交互与当前状态，其余走灰阶；
7. **页头呼吸感**：每个页签页头使用极淡径向渐变（`color-mix` 合成 9% 强调色），让长页面有层次而不花哨；
8. **深浅色自动适配**：通过 `prefers-color-scheme` 一次性适配，两个主题共用同一套变量。

**组件库**：分段控件（SegmentedControl）、标签组（Tag/Chip）、对比图（Compare）、样本条（Samples）、键值表（KV）、时间轴（Timeline）、工单卡（WorkOrder）、洞察卡（Insight）、统计行（Mini stats）。

**工程约束**：坚持**零外部依赖**（不引入任何 CDN 字体、图标库、前端框架），全部资源本地化，断网可完整渲染；样式与结构分离，`index.html` 内**不含任何内联 `<style>` 块**。

**验证手段**：新增 `src/check_frontend.py` 做静态自检——比对 HTML 中定义的 id 与 JS 引用的 id 是否一致（前端无构建链路，id 写错不会报错、只会静默失效）、校验页签与区块一一对应、确认无外部网络依赖。实测 39 个引用全部命中。

**可解释性可视化**：检测结果页提供「原图 / 缺陷标注 / Grad-CAM 热力图」三联对照（`src/viz_heatmap.py` 亦可批量生成专题图）。实测热力图高亮区与真实缺陷位置吻合——夹杂的块状、斑块的两个亮斑、麻点的点阵、氧化铁皮的条带均被准确定位，说明模型依据的是缺陷本身而非背景纹理，这是工业 AI 落地最需要排除的风险。

### 5.3 候选框融合与可视化实现

**问题一：同一缺陷被重复框出多遍。**
滑窗步长 112、窗口 224（50% 重叠），且使用双尺度，实测一张图上同一处缺陷会产生 5~7 个高度重叠的框，前端画面杂乱、严重度也无法解释。仅靠 NMS 无法解决——不同尺度的窗口大小差异大，IoU 很低但显然是同一缺陷。

**修正**：在 NMS 之前增加一层**候选融合**（`_merge_candidates`）：

1. 用"交叠面积 / 较小框面积"代替 IoU 判定同一性（IoU 会被大并集稀释，导致该合并的没合并）；
2. 逐类别、按置信度从高到低贪心分组；
3. **并集膨胀约束**：合并后并集面积不得超过合并前较大框面积的 1.6 倍，否则视为不同位置的缺陷而不合并。若缺此约束，"链式重叠"会一路把框并到覆盖整张图——开发中实测出现过 256×256 的全图框；
4. 组内取最高置信度，坐标取组内并集。

**问题二：中文标签显示为乱码。**
OpenCV 的 `putText` 只支持 Hershey 矢量字体，**无法渲染中文**，实测图上标签显示为 `?????? 0.98 D`。

**修正**：标签改由 PIL 绘制，按平台常见路径依次探测中文字体（Windows 的 msyh/simhei/simsun、Linux 的 wqy/Noto CJK、macOS 的 PingFang），并加入标签纵向避让，避免多个框的标签互相压盖。相关可视化核验脚本为 `src/visualize_result.py`（输出"原图 / 标注图 / Grad-CAM 热力图"三联图），可直接用于人工复查与文档插图。

### 5.4 置信度校准与人工复检策略

系统计算 ECE（期望校准误差）评估置信度可靠性。当置信度低于 0.7 时，`self_check` 工具会将结果标记为"需人工复检"，而不是强行判定。这一设计把模型的"不确定"显式暴露给质检员，是工业场景下比单纯追求准确率更重要的工程取舍。

### 5.5 三级推理后端与降级

```
backend_priority: [rule, ollama, openai_compat]
```

- `rule`：确定性规则 + 知识库抽取，永远可用，可离线复现；
- `ollama`：本地大模型（如 Qwen3 系列），数据不出厂；
- `openai_compat`：任意 OpenAI 兼容云 API，用于演示更强推理能力。

降级时在结果中记录 `degraded_reason`，并在报告与前端展示，保证过程透明。

> 许可说明：本项目在文档中不推荐使用 Qwen2.5-VL-3B-Instruct 等采用 `qwen-research`（仅限研究、不可商用）许可的模型作为企业交付卖点；本地后端建议选用 Apache-2.0 或 MIT 许可的模型。

### 5.6 数据与结果的完整留痕

每次检测记录：检测编号、时间、批次、原始图像路径、图像尺寸、滑窗数量、全部缺陷坐标与置信度、严重度、判定结论、耗时、智能体建议与引用条目。满足 GB/T 40659-2021 对在线检测系统可追溯性的要求，也便于赛后复盘与模型迭代。

## 9 创新点与技术特色

1. **从"检测"到"处置"的闭环**：现有低成本方案止步于缺陷识别，本作品用智能体补齐根因分析、工艺纠正、工单联动与批次追溯，形成"感知—决策—执行"闭环。
2. **确定性判定 + 大模型增强的混合架构**：质量判定由规则与阈值完成，保证可复现、可审计；大模型只做解释与建议生成，规避幻觉影响质量判定。
3. **零额外依赖的核心链路**：检索、可解释性、报告生成均自研实现，演示环境无网络、无法安装第三方包时仍能完整运行。
4. **面向小样本冷启动的数据策略**：程序化合成缺陷 + 公开真实数据 + 企业自有数据三层递进，并支持参数化压力测试，直接回应政策文件提出的"小样本标注缺陷数据微调"。
5. **许可干净的工程选型**：检测主干采用 BSD-3 许可的 torchvision 主干而非 AGPL 的 YOLO 系，便于企业交付；文档中对各模型许可风险逐项说明。
6. **置信度校准驱动的复检策略**：计算 ECE 并把低置信度结果显式转为人工复检，而非强行判定，符合工业质量管理的实际逻辑。

## 附录 B 术语表

| 术语 | 说明 |
|---|---|
| 滑窗（Sliding Window） | 用固定大小窗口在图像上按步长滑动切块，逐块分类实现定位 |
| NMS | 非极大值抑制，合并重叠检测框 |
| Grad-CAM | 基于梯度的类激活映射，用于可视化模型关注区域 |
| ECE | 期望校准误差，衡量预测置信度与实际准确率的一致性 |
| BM25 | 经典概率检索模型，含词频饱和与文档长度归一化 |
| RAG | 检索增强生成，先检索知识再生成回答 |
| 严重度分级 | 按缺陷风险、置信度与面积综合评定 A~E 五个等级 |
