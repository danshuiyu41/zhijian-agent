## 三、逐项界定：哪些是自己的设计，哪些用了 AI 辅助

### 3.1 完全自主设计（AI 未参与决策）

| 内容 | 说明 |
|---|---|
| **选题与场景定义** | 面向中小金属加工厂"缺质检人力、缺陷判级依赖老师傅经验"的痛点，选取表面缺陷检测 + 处置闭环这一垂直场景。 |
| **严重度分级公式（v2）** | 嵌套加权：`100·[w_risk·R + (1-w_risk)·(w_conf·C + w_area·A)]`，权重 0.55/0.20/0.25，风险等级做先验、置信度与归一化面积做修正。三档阈值 A≤28 / B≤42 / C≤60 / D≤80 / E≤100 由我们自己在留出集上标定得到。 |
| **多尺度滑窗 + 候选融合策略** | 尺度 1.0/0.6、窗口 224、步长 112；重叠度 ≥0.30 且并集膨胀 ≤1.6 时合并候选框；再按类做 IoU 0.35 的 NMS。融合规则是我们为"同一缺陷被多窗口重复检出"这一问题专门设计的。 |
| **开集拒识方案** | 用倒数第二层 576 维特征做 L2 归一化，取 k=5 近邻距离作 OOD 分数，阈值 0.5155 由 `runs/ood_eval.json` 在已知/未知集上权衡得到。 |
| **智能体架构** | 5 个工具 + 三级降级后端（规则 → 本地模型 → 在线模型），**判定权收归确定性规则**，大模型只负责措辞组织。意图分类器显式拒答"讲一下基本原理"这类泛问。 |
| **知识库内容** | 24 条（含 6 条排查顺序），条款号、判定依据、处置动作均由我们查阅国标与工艺资料后整理。 |
| **指标体系与实验设计** | 评测口径（准确率、macro-F1、ECE、鲁棒性 L1/L2/L3、端到端时延、吞吐）由我们设定，并主动做了"合成数据 vs 真实数据"的可信度说明。 |
| **前端设计系统** | 深色优先的 token 化设计系统、四页签信息架构、异步热力图加载，均为自主设计。 |
| **9 项自检脚本** | 针对开发中实际踩过的坑（全角引号、CSS 变量残留、接口不存在、对比度不足等）自行编写。 |

### 3.2 使用 AI 辅助，但由队员改写与验证

| 内容 | AI 做了什么 | 队员做了什么 |
|---|---|---|
| 部分 Python 实现 | 生成初版函数骨架、补全样板代码 | 逐行通读、改写为符合本项目结构、实测验证 |
| 排错 | 根据报错信息给出候选原因 | 定位真因（如 `net(x)` 返回池化向量而非特征图、`avgpool` 被丢弃导致维度不匹配）、自行修复 |
| 文档措辞 | 润色语句、调整结构 | 提供全部技术事实与数据，核对每条结论，删除 AI 的过度表述 |
| 资料检索 | 帮助定位国标条款名称与政策原文 | 逐条核对原文出处，只保留可验证的引用 |
| 前端样式微调 | 提出配色与间距建议 | 用对比度检查脚本量化验证，按设计系统落地 |

### 3.3 明确**没有**交给 AI 的部分

- 选题方向与商业/应用价值判断
- 任何算法公式的设计与最终取值
- 阈值、权重、分级边界的标定
- 实验结论与作品局限性的判断（"指标来自合成数据"这一自我批评是我们主动写进去的）
- 团队分工与项目管理
- 最终成文的每一处技术论断
